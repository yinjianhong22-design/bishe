**Goal:** 修订 `技术方案.md`，消除评分、相似案例、冲突检测和证据链设计中的矛盾，并补齐 P0 功能与交付设计。

**Architecture:** 保留现有业务流程、8 个模块和开发顺序四个主体部分，在原章节内修订。相似案例先进入事实表，再由声明式规则参与评分；无规则命中时仍返回安全。规则引擎保留全量匹配，通过可选互斥组表达需要遮蔽的规则关系。

**Tech Stack:** Markdown、Obsidian 链接、现有 FastAPI/PostgreSQL/FAISS/BGE/Vue 3 技术约束。

**Spec:** `需求规格说明书.md`、`毕设任务书-完整版.md`；修订对象为 `技术方案.md`。

## Global Constraints

- 只修改 `技术方案.md`，本轮不修改需求规格说明书、任务书、数据源清单和流程图。
- 保留现有 8 模块编号和主要章节顺序，允许增加子章节、接口文件、页面和数据表。
- 后端保持 FastAPI + Python 3.11，验收数据库保持 PostgreSQL，向量检索保持 FAISS + BGE 中文模型。
- HTTP 模块使用 `APIRouter` 组织路由，使用 `Depends` 注入引擎、服务和权限依赖；引擎内部直接调用 Python 函数，不把内部调用改成 HTTP 请求。
- LLM 不输出可直接生效的风险分或风险等级；本地代码根据校验后的枚举值查配置并计算语义分。
- 无规则命中时必须返回“安全”；相似案例只能通过声明式规则影响分数。
- 文档中的性能数值属于设计预算，实施后仍需按 E7 实测，不能写成已经达标。
- 当前目录不是 Git 仓库，各任务不安排提交步骤，也不初始化 Git。
- 本计划采用“相似案例事实 + 声明式规则评分”的方案 A；批准本计划即确认该设计方向。
- 修订时将 frontmatter 的 `updated` 改为实际修订日期，并在关键设计决策中记录未采用“相似案例仅展示、同步放宽 E3”的原因。

## Review Focus

- 变形还原改变字符串长度：原文证据必须仍等于 `original[span_start:span_end]`，由任务 2 检查。
- 组合条件跨两个文本分段：整文规则匹配必须仍能命中，由任务 2 检查。
- 零规则命中但 LLM 返回高危意图：最终必须仍为安全，由任务 1 检查。
- 同一互斥组内的宽泛规则抢先命中：静态分析必须报告具体规则遮蔽，由任务 3 检查。
- LLM 超时或返回非法 JSON：核心判定须在时限内降级返回，由任务 4 检查。

### Task 3: 重写冲突检测和热更新机制

**Files:**
- Modify: `技术方案.md:155-183`（DSL 与冲突检测）
- Modify: `技术方案.md:260-268`（运营存储）
- Modify: `技术方案.md:284-289`（数据层）

**Interfaces:**
- Consumes: 任务 1 的 `participates_in_score` 和 `suppressed_by` 轨迹字段。
- Produces: 可选 DSL 字段 `exclusive_group: string | null`、`priority: integer`；默认 `null` 表示全量命中并累加。

- [ ] **Step 1: 明确全量匹配与互斥组语义**

在 M2.3 写明：未配置互斥组的规则全部参与评分；同一互斥组内仅最高优先级的命中规则参与评分，其余命中规则保留在轨迹并标记 `suppressed_by`。同优先级使用固定 `rule_id` 顺序决胜，保证回放可复现。

- [ ] **Step 2: 给出可实现的冲突定义**

替换“条件真子集且权重较小即遮蔽”的算法：

- **遮蔽**：仅在同一互斥组内判定。若 B 的条件能推出 A 的条件，且 `priority(A) > priority(B)`，或优先级相同且 `rule_id(A) < rule_id(B)`，则 B 会被 A 遮蔽。静态分析只对可证明包含关系的扁平肯定条件给出确定告警，遇到 `not`、复杂 `any` 或无法比较的正则时标记“需人工分析”。
- **冗余**：在同一互斥组内，规范化条件 AST、优先级和评分效果一致时报告冗余；仅关键词集合相同但嵌套结构不同的规则不得判为等价。
- **重复条件**：互斥组外的相同条件会重复计分，只报告“条件重叠”；组内相同条件但权重或优先级不同的规则也报告重叠，不混入确定冗余数量。

- [ ] **Step 3: 设计跨进程热更新**

保留“DB 为唯一事实源、先编译再原子切换”。将 `asyncio.Event` 限定为单进程即时通知；多 worker 每 1 秒轮询配置版本，因此跨进程生效上限为 1 秒加编译时间。规则、阈值、语义配置、变形词表和黑白名单使用各自版本号，编译或校验失败时继续使用上一版本。

- [ ] **Step 4: 检查本任务验收项**

桌面验证五种关系：默认模式下两条规则同时得分、互斥组内具体规则被宽泛高优先级规则遮蔽、同组同效果同条件规则报告冗余、结构不同但关键词相同的规则不误报等价、编译失败时旧规则继续服务。确认“命中规则逐条展示”包含被抑制规则。

- [ ] **Step 4: 固定实验指标口径**

在攻防平台或需求追踪部分补充公式，实验期间固定“检出”定义为风险等级达到中风险或高风险：

```text
召回率 = 被检出的诈骗样本数 / 诈骗样本总数
变体 ASR = 原始样本已检出、但变体未检出的配对数 / 原始样本已检出的配对总数
注入 ASR = 成功促使系统降低风险等级或接受非法模型输出的注入样本数 / 有效注入样本总数
```

E3 使用同一新型变体集比较纯规则与混合模式召回率；E4 只统计原始样本与变体一一对应的样本；E5 对同一注入集分别运行防御开关，并同时报告绝对 ASR 和相对下降比例。风险等级不变的解释文本异常不计入“降低风险等级”，但应单独计入输出校验失败数。
