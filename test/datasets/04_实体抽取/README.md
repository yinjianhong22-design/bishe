# 04 实体抽取测试集 —— 说明与构建方案

对应需求：§3.3.1 五类实体抽取（电话号码、银行卡号、网址、金额、App 名称）；
验收指标 E2：总体准确率 ≥90%（App 名称可放宽至 ≥80%）。

## ⚠️ 无现成数据集，需半自动构建（预计 3–5 天）

没有公开的"诈骗短信五类实体标注语料"，但五类实体格式规则性强，
按清单方案：**从 FBS_SMS / SpamMessage 语料正则半自动标注 + 人工校对**，数百条即可满足 E2。

## 构建流程建议

### 第一步：规则初标（半天）

对语料逐条跑下列正则/规则，生成候选标注（BIO 或 span 均可）：

| 实体 | 初标方法 | 备注 |
|---|---|---|
| 电话号码 | 正则 + 号段校验 | 手机号 `1[3-9]\d{9}`；固话区号；400/95/96 特服号；境外 `00+` |
| 银行卡号 | 正则 `\d{16,19}` + **Luhn 校验** | Luhn 过滤误报（对齐技术方案 M2.2） |
| 网址 | 正则 | `http(s)://...`、`www.`、短链（t.cn、d.cn 等）、裸域名 |
| 金额 | 正则 + 中文数字解析 | `xx元/万/块`、"人民币 xx"、"DIGIT 万" 等 |
| App 名称 | 词表匹配 + 上下文 | 微信/支付宝/抖音/淘宝…+ "下载xxApp" 句法模板；最难，指标放宽至 80% |

### 第二步：人工校对（2–3 天）

- 从初标结果中分层抽样（每类实体 ≥100 条，覆盖正/负例），逐条核对 span 边界；
- 重点校对**易混场景**：金额 vs 数量（"贷 5 万"是金额，"5 天内下卡"不是）、电话 vs 卡号位数重叠、变形书写（"微 信""VX"）。

### 第三步：格式与冻结

建议 JSONL：`{"id": ..., "text": "...", "entities": [{"type": "phone|bank_card|url|amount|app", "start": n, "end": m, "text": "..."}]}`，
坐标基于**原文**（对齐技术方案 boundary_map 要求，预处理后的规范化文本需能映射回原文 span）。

## 已有素材对五类实体的覆盖情况

| 实体 | FBS_SMS 覆盖 | 说明 |
|---|---|---|
| 电话号码 | ⚠️ 仅占位符 | FBS 已匿名化为 `CELLPHONE/PHONE/HOTLINE`——可验证占位符级规则，**真实号码形态需自行构造或从 SpamMessage 补充** |
| 银行卡号 | ⚠️ 仅占位符 | 同上（`BANK` 占位符，FR_Other 中有转账场景） |
| 网址 | ⚠️ 仅占位符 | 同上（`URL` 占位符）；真实 URL 形态可从 OpenPhish/URLHaus 黑名单反取 |
| 金额 | ✅ 较好 | `DIGIT` + 量词上下文保留，结合中文数字可标 |
| App 名称 | ✅ 较好 | 微信/QQ 等以占位符或明文出现，词表可建 |

→ 建议再构造 100–200 条**含真实形态实体**的合成短信（基于 FBS 模板回填真实格式号码/卡号/链接），
本目录预留 `合成样本/` 子目录存放。
